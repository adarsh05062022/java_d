# Fixing Berka: five interventions, measured separately

> **Note, 5 Oct 2026.** Loan-default numbers in this document were computed with a date window that ended 185 days before each loan (raw stored dates compared across tables, which count from different days). The corrected numbers are in `reports/grdm-final-report.html` and `docs/downstream/RESULTS_downstream.md`; card-ownership numbers are unaffected.

Companion to `DIAGNOSIS.md` (why Berka fails) and `RESULTS_downstream.md` (the measured numbers,
regenerated by `downstream/report.py`). This file records what each fix changes in the code and
what it bought.

Every fix is **flag-gated and off by default**. `downstream/redecode.py --decoding round --verify`
reconstructs the stored baseline output from the cached sample and asserts it matches, so the
reproduction in docs/REPRODUCTION.md §2/§8 is provably untouched.

Each experiment writes to its own workspace (`rdbdiff_workspace/berka_split_<fix>/`) and its own
results JSON, and every variant is scored on the **same fixed split and test set**. Only one thing
differs per row, so a delta is attributable to that change.

## S1 — Distribution-matched categorical decoding

**Hypothesis (H2).** Categorical columns are Gaussian-diffused as ordinal integer codes and
decoded with `np.round`, which thresholds at midpoints between codes. `loan.status` class B
collapses from 24 real rows to 1–10 synthetic.

**Change.** `decode_categorical_matched` in `rdbdiff/utils/data.py`: keep the ordering the model
produced, but place the decision thresholds where the *real* class proportions say they belong
(largest-remainder apportionment over the sorted synthetic values). Codes absent from the real
data receive no mass, so gaps in the label encoding survive. Exposed as
`--categorical_decoding {round,match}`; non-default values write to a separate output directory.

Requires **no retraining** — sampling is the expensive stage and its output is cached, so
`downstream/redecode.py` re-decodes in seconds. This is also how the baseline-identical guard
works: `redecode.py --decoding round --verify` reruns the same code path with the upstream
decision rule and asserts the result matches the stored CSVs exactly.

**Result: the marginal is fixed and it changes almost nothing downstream.**

| | real | baseline | S1 |
|---|---|---|---|
| `loan.status` class B (3 seeds) | 24 | 1 / 6 / 10 | 24 / 24 / 23 |
| default rate | 0.112 | 0.073–0.080 | 0.110–0.113 |
| card AUROC (3-seed mean) | 0.8739 | 0.6021 | 0.6009 |
| loan AUROC (3-seed mean) | 0.8886 | 0.5917 | 0.5963 |

This is the most useful negative result in the set. The minority-class collapse is the most
*visible* symptom — it is what a fidelity table would flag — and repairing it perfectly across all
three seeds moves downstream utility by +0.0046 on loan and −0.0012 on card, both within noise.
**H2 is real and reproducible, and it is not load-bearing for downstream utility.**

## S2 — Deeper conditioning (`n_hops=2`)

**Hypothesis (H1).** The GNN has `n_hops` layers, so a row is conditioned on its own noisy
features plus its direct neighbours' raw columns. Generating a `loan` sees its account's two
columns; the account's ~235 transactions are two hops away. A `card` sees only `disp_type`.

**Change.** Configuration only — `--n_hops 2 --num_neighbors -1 16`. No code change.

The fan-out cap is not optional: `--num_neighbors -1 -1` pulls **~941,000 nodes per batch**
(a `trans` seed drags in its account's ~235 siblings) versus ~12,700 at one hop. `-1 16` costs
~77,000. Note `num_neighbors` is shared by the training dataloader and the sampler, so training
and sampling stay consistent.

**Result: nearly doubles retained signal on the dependency task (27.3% → 45.1%, 3-seed mean),
and makes loan default noticeably worse (23.6% → 6.8%).**

Card ownership is the fix the diagnosis predicted, and A2 in `DIAGNOSIS.md` confirms the mechanism
quantitatively: the baseline generator scores ~0.60 against an *own-row-only* real ceiling of
0.604, and S2 scores ~0.67–0.69 against a *1-hop* real ceiling of 0.671. The effective conditioning
window sits one hop behind the nominal depth — a neighbour's features are themselves still noisy
while the row is generated.

Loan default going down, confirmed now across 3 seeds (0.6418 single-seed pilot → 0.5264 ± 0.122
three-seed mean, with one seed as low as 0.44), was not predicted by H1 and is not fully explained.
The working theory: `n_hops=2` widens every table's effective batch (§ fan-out above), which dilutes
`loan`'s already-thin 2.6-seeds-per-batch share further in relative terms even though the absolute
count is unchanged — the model spends a larger fraction of every batch's capacity attending to
`trans` neighbourhoods. This is exactly the interaction S3 targets, which is why S5 (below) recovers
most of what S2 loses on loan while keeping its card gain.

Fidelity **drops** while utility rises on card (Column Shapes 96.86 → ~95.0, 1-HOP 90.38 → ~89.3).
The two axes are not merely uncorrelated here; on this fix they move in opposite directions.

## S3 — Balanced seed sampling

**Hypothesis (H3).** Seeds are drawn uniformly over rows and the loss is computed on seed nodes
only, so per-batch gradient is proportional to table size: `trans` 4007.8 seeds, `loan` 2.6.

**Change.** `WeightedRandomSampler` over eligible seed nodes with weight ∝ `count(type) ** -alpha`
in `rdbdiff/dataloader.py`; `--seed_balance_alpha` (0 = upstream, 1 = equal per table). Run at
α=0.5, which lifts `loan` from 2.6 to 78.2 seeds per batch while `trans` keeps 3052 — full
balancing would starve `trans`, which is 98% of the data and whose own quality still counts.

`rdbdiff/trainer.py` needed its epoch assertion relaxed: sampling with replacement means the
per-epoch visit count is a random variable, so only the total is checked, and the per-type loss
average guards against a type going unvisited. Epoch-boundary checkpointing is preserved.

**Result: the strongest single fix for loan default (23.6% → 41.5%, 3-seed mean) and a smaller,
still-real gain on card (27.3% → 31.1%).** Unlike S2, S3 is the only fix that **improves fidelity
over baseline** rather than trading it away: Column Shapes 96.86 → 96.82–96.99 across all three
seeds, 1-HOP 90.38 → 91.78–91.91. More gradient for the small tables appears to be a pure win with
no visible cost, which is the cleanest result in this set.

## S4 — One-hot categoricals

**Hypothesis (H2), at the model level.** Remove the false ordinal metric entirely rather than
patching the decoder.

**Change.** `--categorical_encoding onehot`: discrete columns are expanded to one-hot in
`make_pkey_fkey_graph`, excluded from the quantile transform, and decoded by argmax.

**Result: harmful everywhere, dropped after one seed.** On Berka: card 27.3% → 9.6%, loan
23.6% → 13.5%, and fidelity fell further than S2's (1-HOP 90.38 → 80.82). The California
regression guard was decisive: synthetic-only R² went from 0.5244 to **−4.9684** (worse than
predicting the mean) and macro-F1 from 0.6749 to 0.3533. That result stopped further Berka seeds
from being run — a fix that breaks the database that already worked is not worth chasing further,
regardless of what it might do on the failing one. Gaussian diffusion over a one-hot simplex plus
argmax decoding evidently loses far more than the ordinal metric it removes. Full discrete/
multinomial diffusion (the parent class's unused `num_classes` path) remains the untried
principled option, and would not share this failure mode since it never treats the simplex as
Gaussian.

## S5 — S2 + S3 combined

**Hypothesis.** S2 (depth) and S3 (gradient balance) target different mechanisms, and S3
independently addresses part of what makes S2 costly: it cuts `trans`'s share of every batch,
which is the same fan-out that 2-hop conditioning has to pay for.

**Change.** Both flags together: `--n_hops 2 --num_neighbors -1 16 --seed_balance_alpha 0.5`. No
new code.

**Result: the best card-ownership number of any fix (48.5%), and recovers most of S2's loan-default
loss (34.0%, vs S2 alone at 6.8%, vs S3 alone at 41.5%).** This is consistent with the theory in
the S2 section above — S3's gradient rebalancing offsets the dilution that 2-hop conditioning
otherwise imposes on `loan`, while keeping the wider window that helps `card`. Fidelity (Column
Shapes 94.48, 1-HOP 88.82) sits close to S2 alone, so the combination does not recover the fidelity
that depth costs — only the downstream utility.

Single seed so far; seeds 1–2 and the California guard are the natural next runs if this line of
work continues.

## What this adds up to

All three root causes turn out to be load-bearing, but not equally, and not independently.
**Conditioning depth (H1)** is necessary for the cross-table dependency task and actively harmful
to the single-parent-aggregate task on its own — it only becomes strictly better than baseline on
loan when paired with **balanced sampling (H3)**, which is the best fix in isolation and the only
one that improves fidelity rather than spending it. The categorical-encoding cause (H2) is
genuinely present in the marginals and reproducible across seeds, but neither repairing its
symptom (S1) nor removing its mechanism (S4) helps downstream utility, and S4 actively destroys
it on both databases.

The practical recommendation for anyone generating a deep relational schema with GRDM: set
`n_hops` to at least the distance between a row and the tables that carry its predictive signal,
cap `num_neighbors` beyond the first hop so the batch stays tractable, and pair any increase in
depth with balanced seed sampling — depth alone can cost more on the tables it does not target
than it gains on the one it does. The published `n_hops=1`, uniform-sampling default is well
matched to a two-table schema like California and badly matched to Berka on both axes at once.

## S8–S13 — changing the denoiser, not its inputs

S1–S7 all left the network alone: they changed how categoricals were coded, how deep the
neighbourhood sampler reached, how seeds were drawn. S8–S11 change the denoiser itself. Each is
layered on **S5** (`--n_hops 2 --num_neighbors -1 16 --seed_balance_alpha 0.5`), the best
downstream configuration the earlier fixes produced, so a delta is against S5 rather than against
the published baseline.

All four are off by default, and `rdbdiff/gnn.py` keeps relbench's `HeteroGraphSAGE` on the
default path rather than reimplementing it, so a baseline run is bit-identical to the published
one — verified by building both modules under one seed and comparing every parameter tensor and
the forward output, not by inspection.

|---|---|---|---|---|
| S5 baseline | 0.059 | 1.00 | 3.3 | 12.07M |
| +S9 residual GNN | 0.060 | **1.01** | 3.3 | 12.07M |
| +S10 degree features | 0.066 | **1.11** | 3.7 | 12.07M |
| +S8 multi-statistic aggregation | 0.085 | **1.44** | 4.7 | 13.64M |

### S8 — multi-statistic aggregation (`--gnn_aggr sum mean max std`)

**What is wrong.** Every config here sets `gnn_aggr: "sum"`, so a row is conditioned on exactly
one statistic of each child table. A downstream model's features over that same child table are
counts, means, extremes, spreads and code fractions. A denoiser that only ever sees the sum
cannot reproduce a correlation that lives in the spread, because it never observes the spread.

**Change.** `aggr` accepts a list; each `SAGEConv` becomes a PyG `MultiAggregation` that
concatenates the statistics before the linear map. `rdbdiff/gnn.py`.

### S9 — residual message passing (`--gnn_residual`)

**What is wrong.** relbench's stack is `conv → LayerNorm → ReLU` at every layer including the
last. Each hop rewrites the representation rather than adding to it, and the terminal ReLU hands
the MLP heads a non-negative vector. That is a plausible mechanism for the S2 result — depth
bought the cross-table task 18 points and cost the single-parent task 17, which is a trade, not
an addition.

**Change.** Residual connection around each layer and no activation on the last.
`RelationalGraphSAGE` in `rdbdiff/gnn.py`. Free: 1.01x.

### S10 — exact per-relation cardinality (`--degree_features`)

**What is wrong, and why this is the best-targeted of the four.** `--num_neighbors -1 16` hands
the GNN 16 of an account's ~235 transactions, so every aggregate it forms is a fixed-size sample
whose size says nothing about the real fan-out. Cardinality is not a nuisance here — it *is* the
label on one of the two tasks: `berka_card_ownership` asks whether a disposition has a card,
which is exactly `degree(disp ← card) > 0`. §5 H4's A5 test showed a synthetic-trained model
scores 0.5702 on synthetic test data, i.e. the relationship is genuinely absent rather than
merely distorted. With this flag the disposition's embedding literally contains that count, and
an account's contains its transaction count.

The structure is sampled in full *before* any attribute is generated, so the true degrees are
available at generation time exactly as they are at training time — this is conditioning on
something the pipeline already knows, not leakage.

**Change.** `add_relation_degrees` in `rdbdiff/utils/graph.py` attaches a dense
`(num_nodes, num_edge_types)` `log1p` degree block to every node type; the denoiser projects it
and adds it to the node embedding. The uniform width across node types is what lets the block
survive the `to_homogeneous`/`to_heterogeneous` round trip the dataloader performs, and the
columns are indexed by *sorted* edge type so the real graph and the sampled structure graph agree
on which column means which relation.

### S11 — self-conditioning (`--self_conditioning`)

**What is wrong.** DIAGNOSIS.md A2 measured that the effective conditioning window sits one hop
behind the nominal depth: at `n_hops=1` the generator scores against the *own-row* real ceiling,
at `n_hops=2` against the *1-hop* ceiling. The reason is that a neighbour's features are
themselves at noise level t while the row is being denoised, so at large t the window is empty.

**Change.** Run the denoiser in two passes. The first produces an x0 estimate for every node in
the batch through a single linear head on the GNN representation; the second consumes those
estimates in place of the raw noise. The estimate is fed forward **detached** and supervised by
its own reconstruction loss (`--self_cond_aux_weight`, default 1.0) — without that term the head
would keep its initialisation forever, since nothing else trains it. `sc_projs` is zero-initialised,
so an untrained model is exactly the one-pass model.

Both passes run at training *and* at sampling time, so there is no train/test mismatch. Cost is
one extra GNN forward (1.83x), against ~2.4x for the extra hop it is meant to substitute for.
