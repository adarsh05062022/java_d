Step 3: Experimental-validity audit — findings

None of these invalidate the headline comparisons, but all of them change how the numbers should be read. Findings 7–8 were discovered mid-audit after the original pre-loss repository became reachable again; Finding 8 corrects a claim this audit itself got wrong in its first pass.

FINDING 1

Cardinality is bit-identical across every Berka configuration — not a valid comparison metric

Cardinality is 99.65±0.05 for all five Berka configurations, identical to 12+ significant digits even across separate worktrees/training runs (confirmed: mean=99.64999999999999, sd=0.053541261347361556 repeated verbatim across six keys in comparison.json). It is a property of the shared, deterministic structure-sampling step, unaffected by degree/aggregate conditioning. Do not use it to argue any configuration is better or worse. 3-HOP relational fidelity is similarly flat (92.65–93.05) and should be read the same way.

FINDING 2

Standard-deviation convention differs between the Berka and California tables

Table 1 and Tables 2–3 use population SD (ddof=0), chosen explicitly to keep all Berka columns comparable. Table 4–5 use sample SD (ddof=1), inherited from GRDM_CALIFORNIA_.../compare.py line 35. For n=3, ddof=1 SDs are √(3/2) ≈ 1.22× larger than ddof=0 on the same data — means are unaffected, but raw SDs across the two halves of this report are not on the same scale. Flagged, not silently renormalized.

FINDING 3

Berka and California have genuinely different leakage exposure — by construction, not by accident

All 6 Berka configs carry leakage_caveat=true: the GRDM generator trained on the full data/berka/preprocessed database, which includes the accounts later held out as the downstream test set. California's DATASETS["california"] uses a genuinely separate data/california/train split, leakage=False, inherited by all 3 new fine-tuned arms. Berka's downstream numbers are an upper bound (relative ranking unaffected, absolute levels optimistic); California's carry no such caveat.

FINDING 4

Berka's "aggregate fine-tuned" column in Table 1 reflects a sampling failure, not a clean fine-tuning read

The joint (unfrozen-backbone) fine-tune of the aggregate-conditioned model produces unstable sampling — up to 78% of rows fall outside the real-data range in model space (per the source experiment's own REPORT.html; consistent with the outsized Column-shape drop, 96.44→84.46). Numbers are mechanically comparable but measure this failure mode, not fine-tuning in general. Use the frozen-backbone variant for "does fine-tuning help fidelity" claims.

FINDING 5

Berka and California test different interventions — not a matched pair

Berka's aggregate-conditioning (config 4) is trained from scratch. California has no from-scratch aggregate-conditioned run at all — agg/agg_label_free/control are all continued-training fine-tunes of the existing checkpoint. Any Berka-vs-California "does aggregate conditioning help" comparison is implicitly scratch-vs-fine-tune, not dataset-vs-dataset — the single most important caveat for the cross-dataset questions below.

FINDING 6

Berka's label-free aggregate arms aren't in the main 6-configuration downstream table

berka_aggft_label_free{,_frozen} results exist and are internally consistent but weren't one of the 6 requested configurations, so Tables 2–3 omit them. California's label-free arm, by contrast, is included in Tables 4–5. A scoping asymmetry carried over from the source reports, not an error — "6 Berka configs" and "4 California configs" are not parallel lists.

FINDING 7

Cross-checked against the pre-/scratch-loss original repository: the eval code is identical, the GRDM models are not

2026-10-14: the original checkout became reachable again at /bhallukah/.../rdb-diffusion (the relocated old /scratch mount). Diffed directly against the rebuilt repo:

  • Byte-identical: evaluate.py, data.py, splits.py, tasks.py (incl. the Oct-5 date-offset bug fix, present in both), the entire rdbdiff/ model+training tree, main.py, training configs. run.py differs by one path-only line, irrelevant to Berka.
  • The real regime matches to full floating-point precision — Berka loan-default AUROC 0.938573407202216 in both repos; card-ownership AUROC 0.8739133895876453 in both. Proves the real-data split and eval protocol are unchanged.
  • Everything synthetic-dependent differs, because the original GRDM checkpoints were lost with /scratch on 2026-10-07 and the current baseline is a fresh, stochastic retrain — not a copy. Drift is dataset-dependent: Berka (small, 171 test loans) swings a lot (synth AUROC 0.5316→0.5068 loan, 0.6094→0.5726 card); California barely moves (synth income R² 0.5272→0.5274).

Consequence: every number in Tables 1–5 is correct and internally consistent with the current baseline — but absolute Berka synthetic-only numbers should not be assumed to match any pre-2026-10-07 reporting. Relative comparisons between conditioning variants are unaffected.

FINDING 8 · CORRECTION

The leakage-free Berka baseline (berka_split) is NOT orphaned — this audit's earlier claim was wrong

The original audit stated berka_split's checkpoint and real-data split "no longer exist on disk" — true only inside the java_d worktree family. Now that /bhallukah is reachable again, direct inspection found, fully intact:

  • rdbdiff_workspace/berka_split/paper_repro/seed_{0,1,2}/model_checkpoint/{model.pt,model_ema.pt,checkpoint.pt} — real trained checkpoints (2026-08-09), plus already-sampled synthetic data for every seed.
  • data/berka/split_train/ and split_test/ — verified clean: 3375 train accounts, 1125 test accounts, zero account-ID overlap.
  • Eval code byte-identical to the current repo (Finding 7), so existing berka_split__{task}.json results are genuine, current-protocol, leakage-free results — not a stale pre-bug-fix artifact.

What's still missing is only regime coverage (real/synth/mixed only, no blend_*/real_25/50/75) — fillable without retraining, the same way Table 5's California gaps were closed. Not performed in this audit; flagged as an opportunity, since it touches a shared mount this audit did not attempt to write to.

Nothing fabricated, nothing silently merged. No metric in Tables 1–5 was estimated, interpolated, or backfilled. The one historical leakage-free Berka baseline was deliberately excluded from Tables 2–3 (reasoning in Finding 3) — note its status changed in Finding 8.

Step 5: Interpretation (verified results only)

Q1

Does degree conditioning improve relational fidelity? (Berka only — no California degree-conditioning experiment exists)

Mixed, metric-dependent, and from-scratch only. The four dependency metrics it targets all improve (agg-KS 0.273→0.204, parent-agg-corr 0.141→0.121, agg-agg-corr 0.245→0.180, sign-agreement 0.625→0.764), but the paper's general fidelity metrics mostly drop a little. Degree-fine-tuned is worse than both baseline and degree-scratch on almost every metric — fine-tuning actively hurts fidelity here, it does not just fail to help.

Q2

Does aggregate conditioning improve relational fidelity?

Yes, more cleanly than degree conditioning, consistently across both datasets. Berka aggregate-from-scratch: agg-KS 0.273→0.143, parent-agg-corr 0.141→0.086, agg-agg-corr 0.245→0.076, sign-agreement 0.625→0.884 — the single clearest fidelity win in the whole audit. California aggregate-conditioning (fine-tune): household-summary KS 0.149→0.054, downstream-feature KS 0.111→0.034 — and unlike Berka, California's general fidelity metrics also improve (Column Shapes 98.573→98.971, 1-HOP 96.447→97.071). Caveat: Berka's arm is from-scratch, California's is fine-tuned (Finding 5) — not a fully matched comparison.

Q3

Which approach performs better on each relevant fidelity metric? (Berka, where both exist)

Aggregate-conditioning-from-scratch beats degree-conditioning-from-scratch on all 4 dependency metrics and 3 of 4 paper-suite relational metrics. Aggregate conditioning is the stronger fidelity intervention on Berka, full stop.

Q4

Do fidelity improvements translate into improved downstream prediction?

Not reliably — the most important finding of the audit, now confirmed across the full 11-regime California sweep. On Berka, yes: the two configs with the biggest fidelity gains also uniquely beat the baseline on synthetic-only AUROC/AP/F1 (aggregate-scratch loan AUROC 0.507→0.826). On California, no: aggregate-conditioning gave the largest fidelity improvement in the audit but downstream utility is flat-to-slightly-worse than Control in every one of 11 regimes, both tasks. Likely reconciliation (not provable here): Berka's winner is from-scratch, California's is fine-tune, and Berka's own fine-tuned arms also fail to transfer fidelity gains — so the real split may be scratch-vs-fine-tune, not Berka-vs-California.

Q5

Are results consistent between Berka and California?

Partially, only where the comparison is apples-to-apples. Consistent: aggregate conditioning improves targeted dependency/KS fidelity substantially in both (Q2). Inconsistent on the surface: downstream gain on Berka, none on California (Q4) — but this compares a scratch arm to a fine-tune arm, a confound this audit cannot remove. Not comparable at all: degree conditioning and the from-scratch regime (Berka only).

Q6

Which findings are statistically or experimentally uncertain?

No significance testing (t-test, bootstrap CI) was performed anywhere. The large fidelity and synthetic-only downstream effects (gaps of several SDs) are unlikely to be pure noise. Several blend/mixed-regime downstream rows are not: e.g. degree-scratch loan-default AUROC beats baseline at blend_50 (0.903 vs 0.878) while its AP is indistinguishable (0.611 vs 0.615) — a single-metric "win" with a sub-0.02 gap and SD>0.02 should read as noise.

Q7

Are the downstream results affected by potential data leakage?

Yes for Berka (all 6 Table 2–3 configs, Finding 3) — optimistic upper bound, relative ranking unaffected. No for California (Finding 3). Update (Finding 8): a genuine leakage-free Berka baseline (berka_split) also exists and is usable — previously wrongly reported as unrecoverable. Its synth-only AUROC is higher, not lower, than the leaky baseline's (loan 0.514 vs 0.507; card 0.602 vs 0.573) — the opposite of a naive leakage story, but confounded by a smaller training set and a different checkpoint entirely, so not a clean isolation. Flagged as open, not resolved.

Q8

What evaluations are still needed before a strong conclusion?

(a) 42 pending California cells — done 2026-10-14. (b) A California aggregate-from-scratch run, to separate "fine-tuning fails to transfer" from "California specifically doesn't benefit" — still missing, the single largest remaining gap requiring new training. (c) A non-orphaned leakage-free Berka baseline — corrected: it already exists (Finding 8); only its regime sweep is missing, fillable without retraining. (d) Formal significance testing, if a stronger claim than "consistent direction across 3 seeds" is needed.

Final summary

Across Berka, aggregate-conditioning trained from scratch is the strongest intervention tested: it improves every targeted relational-dependency metric by a wide margin and is one of only two configurations (with degree-conditioning-from-scratch) that improves downstream synthetic-only prediction utility on both tasks and all three metrics. Fine-tuning either scheme onto an existing checkpoint consistently underperforms from-scratch training, and in the aggregate case destabilizes sampling outright (joint fine-tune) — a frozen-backbone fine-tune is safe but gives much smaller gains.

On California, aggregate-conditioning (tested only as a fine-tune) produces the largest relational-fidelity improvement seen in this audit, confirmed genuine by an ablation check — but this fidelity gain does not transfer to downstream prediction utility in any of the 11 now-evaluated regimes, mirroring Berka's own finding that fine-tuned conditioning is the weaker lever for downstream gains.

All Berka downstream numbers carry an acknowledged, quantified leakage caveat; California's do not, by construction. A genuine leakage-free Berka baseline also exists and is usable — this audit's first pass wrongly reported it as unrecoverable; its checkpoint, split, and already-sampled synthetic data all survived at a relocated mount, just temporarily unreachable (Finding 8) — but it only covers 3 of 11 regimes today.

Checked explicitly against a real-data-only reference throughout (Tables 2a/3a): no configuration, in any regime, beats real-data-only performance by a margin larger than its own seed-to-seed SD — synthetic data narrows the gap as more real data is blended in, but does not reliably close it. No formal statistical-significance claim is made anywhere in this report; all comparisons are n=3-seed point estimates.
